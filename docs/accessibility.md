# Accessibility testing

This repo runs [axe-core](https://github.com/dequelabs/axe-core) against every
page of the built site, in a headless Chrome session driven by RSpec and
Capybara. The setup is adapted from
[berkeley-cdss/berkeley-class-site](https://github.com/berkeley-cdss/berkeley-class-site).

As of June 2024 all Berkeley websites must meet WCAG 2.0 AA, and from April
2026 they must meet WCAG 2.1 AA — see Berkeley's
[Digital Accessibility page](https://dap.berkeley.edu/). WCAG 2.2 AA is the
current standard, so the suite checks both:

| Example | Tags | Must pass |
| --- | --- | --- |
| `meets WCAG 2.1` | `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa` | yes |
| `meets WCAG 2.2` | `wcag22aa`, `best-practice`, `section508` | yes |

## Running the tests

```bash
npm ci            # Bootstrap + Font Awesome, which the Sass build imports
bundle install
bundle exec rspec
```

You also need Google Chrome installed. Selenium Manager downloads a matching
chromedriver automatically on first run.

`bundle exec rspec` builds the site itself (`spec/support/jekyll.rb`), serves
`_site` over a local Rack server, and visits every URL in the generated
`sitemap.xml` that ends in `/` or `.html`.

Useful flags:

```bash
bundle exec rspec --next-failure         # one failing page at a time
bundle exec rspec --only-failures        # re-run just what failed last time
bundle exec rspec -e "/photos/"          # a single page
RSPEC_CONFIG_FILE=_config_dev.yml bundle exec rspec   # alternate build config
```

Reports land in `tmp/` (`rspec_output.html` is the readable one) and
screenshots of failing pages in `tmp/capybara/`. The CI workflow uploads those
screenshots as an artifact when a run fails.

## Configuring the suite

Everything tunable lives at the top of `spec/accessibility_spec.rb`:

- `SKIPPED_RULES` — axe rules to switch off site-wide. Useful while working on
  a fix; it should be empty on `main`.
- `EXCLUDED_ELEMENTS` — CSS selectors whose subtree is exempt. Ships with
  `[data-a11y-errors="true"]`, so you can mark a single embed you don't
  control:

  ```html
  <div data-a11y-errors="true">
    <!-- third-party embed, not checked -->
  </div>
  ```

  This is a last resort. Keep the selector as small as possible; a growing list
  is a sign the page needs restructuring instead.
- `SKIPPED_PAGES` — full paths to leave untested. Redirect pages are the main
  legitimate case, since the redirect can race the axe run.

## Notes specific to this site

- The Sass build imports Bootstrap and Font Awesome from `node_modules/`, so
  `npm ci` has to run before the tests. `spec/support/jekyll.rb` fails with a
  clear message if it hasn't.
- `sitemap.xml` is generated by `jekyll-sitemap`. Anything you don't want
  tested (or indexed) needs `sitemap: false` front matter, or an entry in
  `exclude:` in `_config.yml` if it's a static file.
